一 前提条件和准备工作
1 前提条件
我们需要掌握入门级的代数知识以及熟练掌握编程基础知识，并且具有一些
使用 Python 进行编码的经验。
1.1 掌握入门级的代数知识
入门级的代数知识：了解变量和系数、线性方程式、函数图和直方图（熟悉
对数和导数等更高级的数学概念会有帮助，但不是必需条件）。
1、变量
变量来源于数学，是计算机语言中能储存计算结果或能表示值抽象概念，变
量可以通过变量名访问。
2、系数
系数(外文名Coefficient)，是指代数式的单项式中的数字因数。单项式中所
有字母的指数的和叫做它的次数。
3、线性方程式
线性方程也称一次方程式。指未知数都是一次的方程。其一般的形式是
ax+by+...+cz+d=0。
4、函数图
函数 f 的图形（或图象）指的是所有有序对（x,f(x)）组成的集合。
5、直方图
直方图(Histogram)又称质量分布图。是一种统计报告图，由一系列高度不等
的纵向条纹或线段表示数据分布的情况。一般用横轴表示数据类型，纵轴表示分
布情况。
1.2 熟练掌握编程基础知识
熟练掌握编程基础知识，并且具有一些使用 Python 进行编码的经验。本课
程中的编程练习是基于Python 进行编码的，我们强烈建议在开始本课程学习前

2 准备工作
2.1Python 机器学习库与未集成算法的安装介绍
1、Python 机器学习库安装介绍
在使用 Python 时，我们通常会开发多个项目。如果将所有项目需要的包都
全局地安装在电脑上，可能会导致依赖冲突、版本混乱等问题。为了解决这个问
题，我们通常会选择安装Anaconda。
Anaconda 是一个包含了conda、Python 和超过150 个科学包及其依赖项的科
学Python 发行版。它具有可视化图形用户界面（AnacondaNavigator）并且为了
方便新手使用，预先包含了大量的库，如NumPy,Pandas,Scipy,Matplotlib 等。
除此之外Anaconda 具有安装、更新、卸载 Python 包以及创建独立的虚拟环境
等功能。
相较之下，Miniconda 更加轻量级。它只包含了Python 和Conda，但并没有
预装其他的库。Miniconda 用户需要手动安装他们需要的包，这使得Miniconda
的环境更为简洁，可以根据实际需求来安装必要的包，避免不必要的存储占用。
为了让读者熟悉conda 创建虚拟环境以及pip 安装第三方库的流程，后文的
实验将以Miniconda 展开。
2、Python 未集成算法安装介绍
Python 集成在scikt_learn 库中的算法直接调用：
支持向量机（SVM）
K 最近邻算法（KNN）
朴素贝叶斯算法（NaiveBayes）
决策树算法（decisiontree）
随机森林（RandomForest）
GBDT（GradientTreeBoosting）
主成分方法（PCA）
…
而在Python 集成库中，并未集成算法XGBoost 和LightGBM，因此需要手
动安装XGBoost 和LightGBM 算法库。

3、集成学习
集成学习（EnsembleLearning）通过构建并结合多个基分类器来完成学习
任务，有时也被称为多分类器系统（Multi-ClassifierSystem）、基于委员会的学
习（Committee-basedLearning）等。集成学习通过将多个基分类器进行结合，
常常可以获得比单一分类器更为优越的泛化性能。
4、随机森林
随机森林（RandomForest）在以决策树为基分类器构建集成的基础上，进
一步在决策树的训练过程中引入了随机属性选择。参数k 控制了随机性的引入程
度：若令k=d（d 表示特征数目），则基于决策树的构建与传统决策树相同；若
令k=1，则是随机选择一个属性（特征）用于划分；一般情况下，推荐值k=log2d。
各个随机数据子集上同时随机选取特征，各自训练一棵树，最后对各棵树的
预测结果进行集成。结果集成时可以采用投票或者均值这两种方式。一般而言，
如果是分类任务则采用投票法，如果是回归任务则采用均值法。

3、集合
集合（set）和dict 类似，也是一组key 的集合，但不存储value。
集合中的元素有三个特征：
（1）确定性：集合中的元素必须是确定的；
（2）互异性：集合中的元素互不相同，例如：集合A={1，a}，则a 不能等
于1）；
（3）无序性：集合中的元素没有先后之分，如：{3,4,5}和{3,5,4}算作同一个
集合。
set 和dict 的唯一区别仅在于没有存储对应的value，但是，set 的原理和dict
一样。所以，同样不可以放入可变对象，因为无法判断两个可变对象是否相等，
也就无法保证set 内部“不会有重复元素”。
set 与数学中的集合类似，是无序的和无重复元素的集合。因此，在Python
中，set 可以进行交集、并集、补集等操作。

四 项目解读
1 项目背景
随着互联网金融和消费信贷业务的不断发展，越来越多的个人通过金融机构
申请贷款。如何准确评估贷款申请人的还款能力，已经成为金融机构开展信贷业
务时需要解决的重要问题。
传统的信用风险评估通常依赖申请人的信用记录。对于缺少完整信用记录或
没有足够历史借贷信息的申请人，金融机构往往难以准确判断其还款能力，也可
能因此拒绝部分具有正常还款能力的贷款申请人。
利用机器学习技术，综合分析贷款申请人的基本信息、贷款申请信息以及历
史信用行为，可以辅助金融机构识别潜在的违约风险，提高信用风险评估的准确
性。Kaggle“家庭信贷违约风险”项目的核心任务，正是根据申请人的相关数据预
测其偿还贷款的能力。
2 项目解读
本项目数据来源于 Kaggle 平台的“家庭信贷违约风险（HomeCreditDefault
Risk）”竞赛。竞赛提供了贷款申请人的基本信息、贷款申请信息以及历史信贷行
为等数据，要求参赛者建立机器学习模型，根据贷款申请人的相关信息，预测其
发生还款困难的概率，评估贷款申请人的还款能力。
模型需要为测试集中的每一位贷款申请人输出一个预测概率。预测概率越高，
表示模型认为该申请人发生还款困难的风险越高。
本项目使用 ROC-AUC 作为模型评价指标，即计算真实标签与模型预测概
率之间的 ROC 曲线下面积。ROC-AUC 值越大，说明模型区分高风险申请人与
低风险申请人的能力越强。
本项目实质上是一个二分类问题，也就是判断贷款申请人是否会发生还款困
难。

3.1.3 划分方法
下面介绍数据划分的基础方法：
1、留出法（Hold-out）
（1）把数据集分成互不相交的两部分，一部分是训练集，一部分是测试集。
（2）保持数据分布大致一致，类似分层抽样
（3）训练集数据的数量应占2/3 到4/5
（4）为了保证随机性，将数据集多次随机划分为训练集和测试集，然后在
对多次划分结果取平均。
2、交叉验证法（CrossValidation）
（1）将数据集随机分为互斥的k 个子集，为保证随机性，p 次随机划分取
平均。
（2）将k 个子集随机分为k-1 个一组剩下一个为另一组，有k 种分法。
（3）将每一种分组结果中，k-1 个子集的组当做训练集，另外一个当做测试
集，这样就产生了k 次预测结果，对其取平均，称为p 次k 折交叉验证，一般取
k=10，称为十折交叉验证

（1）适用于样本量较小，难以划分时。换句话说，样本量足够时，用自助

六 特征工程
1 准备工作
在 HomeCreditDefaultRisk 任务中，我们的目标是根据客户的贷款申请信
息以及外部征信历史信息，预测该客户是否会出现还款困难，即预测标签
TARGET 的取值。对于这类表格型机器学习任务，特征工程是核心的环节之一。
所谓特征工程，是指从原始数据中提取、转换、组合出能够更有效描述样本
属性的变量，以供机器学习模型使用。模型本身只是对输入特征进行拟合，而特
征工程决定了模型能够看到什么信息、能够学习到多深的规律。在实际项目中，
特征工程往往比单纯调参更能决定模型效果。
在本项目中，特征工程主要围绕三类信息展开：一是客户当前贷款申请的基
础信息，其二是客户在外部征信系统中的历史信用信息，三是基于这些原始字段
进一步构造出的比值、差值、统计、分箱、交叉等衍生特征。通过这些处理，可
以将原始业务字段转化为更适合模型学习的输入空间。
1.1 特征工程相关术语
（1）实例：在本任务中，一个实例对应一笔贷款申请。
（2）标签：预测任务的答案。在本任务中，标签为 TARGET，用于表示客
户是否发生还款困难。
（3）特征：预测任务中描述实例属性的变量。例如客户收入、贷款金额、
征信负债情况等。
（4）样本：一个实例及其对应的特征和标签。训练集中每一行都可以视为
一个样本。
（5）模型：预测任务的统计表示法。机器学习任务中，一般使用训练样本
集训练一个模型，然后使用该模型进行预测。
（6）指标：关于预测结果的一个评估指标，用于评测预测结果的正确程度，
本项目使用 AUC。

2.1 两种分类视角
理解表格特征时，可以从两个视角入手。
第一种视角，是按特征的表现形式分类。从最终进入模型的形式看，特征通
常可以分为:
（1）数值特征：如金额、时长、比例、均值、极值等可比较大小的变量。
（2）离散特征：如类别、状态、等级、分组结果等层级型变量。
（3）二值特征：如是否缺失、是否逾期、是否满足某条件等 0/1 变量。
第二种视角，是按特征的构造过程分类。从“特征是怎么做出来的”来看，特
征通常可以分为：
（1）原始特征：直接来自原始数据表。
（2）预处理特征：来自异常值修正、时间标准化、缺失标记等处理。
（3）数值变换特征：来自比例、差值、乘积、均值、极值等行内变换。
（4）离散化特征：来自分箱、编码和风险分层。
（5）组合特征：来自多个变量的交叉或联合表达。
（6）聚合特征：来自多行记录的计数、求和、平均值、极值、占比等压缩。
（7）质量特征：来自缺失、异常、信息完整度和稳定性。
在后文中，主要采用第二种视角，也就是按“构造过程”来展开，更适合解释
特征工程是怎样一步步完成的。
2.2 提取特征的一般方法
明确了分类视角之后，还需要知道特征一般是怎样提取出来的。从更一般的
表格赛角度看，特征提取通常可以遵循下面这条思路。
1、明确预测对象
在任何表格赛中，首先都要回答“模型到底在预测谁”。一行样本可能代表用
户、商品、订单、一次贷款申请、一次点击或一次交易。
字段梳理 拿到数据以后，先逐列看清楚字段类型、业务含义和数据质量。
通常要关注： 它是数值、类别、时间还是标识； 它有没有大量缺失； 它有没
有异常值或异常编码； 它是否存在长尾、偏态或大量重复值。
这一步的目的，是先知道哪些字段可以直接使用，哪些字段需要先修正。
2、单变量分析

在真正构造新特征之前，通常要先了解单个字段本身的表现。常见分析内容

3、相关性和关联性分析
表格赛里常见的一般做法，是在造复杂特征之前，先看看变量和变量之间、
变量和目标之间有没有明显关系。常见方式包括：数值变量之间看相关系数；类
别变量之间看列联关系；变量与目标之间看分组差异、坏样本率、单变量区分能
力；检查是否存在强共线或明显重复的信息。
相关性分析的意义，不只是做筛选，更重要的是帮助我们发现哪些字段适合
进一步做比例、差值、分箱或组合。
4、单列先做基础加工
这一步可以先把原始字段变成稳定、可用、可解释的基础变量。单列特征最
常见的加工方式包括： 异常值修正； 缺失值填补； 缺失值标记； 时间标准化；
类别编码； 连续变量分箱。
5、在单行内部寻找变量关系
如果一张表本身是一行一个样本，那么最自然的下一步就是在同一行内部寻
找变量之间的关系。最常见的方法包括：用比例描述压力、负担或占比；用差值
描述偏差、间隔或结构差异；用乘积或交互描述共同作用；用均值、极值描述多
来源信号的整体水平。
很多高质量特征并不是来自新数据，而是来自对已有字段关系的重组。
6、类别变量考虑分层与组合
类别特征除了直接编码，还经常可以继续加工。例如：统计某类别出现频率；
把稀有类别合并；将两个类别变量交叉，形成更细粒度的人群标签。
也就是说，类别特征的重点不只是“怎么变成数字”，而是“怎么让模型更容
易识别这类对象的模式”。
7、面对分组关系或一对多结构时做聚合
聚合特征只要数据里存在“一个对象对应多条记录”的结构，例如用户对应多
笔交易、商品对应多次曝光、企业对应多条经营记录，就可以考虑做分组统计。

在表格赛里，缺失和异常常常本身就带有信息。某些字段缺失、某些类别极

码。
10、用验证结果反推特征质量
特征工程不是单纯凭直觉堆特征，而是一个不断试验和筛选的过程。一个特
征是否值得保留，通常要同时看两点：它有没有清楚的业务或结构解释； 它在
训练和验证中是否稳定。
因此，特征提取通常是“提出假设 -> 构造特征 -> 验证效果 -> 保留或舍
弃”的反复过程。
2.3 小结
在构造特征的时候，通常需要考虑以下信息：
（1）这个字段在描述什么。
（2）它和其他字段之间有没有关系。
（3）它是一条记录，还是一串历史。
（4）它的缺失或异常有没有额外信息。
这四个问题之外，还可以再补一个非常实用的问题：它和目标之间有没有明
显关系。因为很多特征工程的灵感，恰恰来自单变量分析和相关性分析之后发现
的区分能力差异。我们可以带着这些问题去审视原始数据，就能比较自然地想到：
哪些字段适合做数值变换，哪些字段适合做离散化，哪些多行记录适合做聚合，

3.2 小结
当前 baseline 的主表特征工程，本质上是在把一张原始贷款申请表逐步改
写成一张客户画像表。它先处理异常值和编码问题，再从偿债能力、家庭负担、

4 征信表特征工程
主表中的一行样本，对应的是“一位客户的一次贷款申请”；而征信相关数据
并不是这个粒度。对同一位客户来说，外部征信里可能有很多历史账户；对同一
笔历史账户来说，又可能有很多个月度状态记录。
这就意味着，征信信息天然是“客户 -> 账户 -> 月度记录”的一对多结构。
如果不先压缩粒度，就无法直接并回主表。也正因为如此，征信特征工程的核心
任务并不是简单拼表，而是把多层历史记录逐步压缩成“每位客户一行”的风险摘
要。
征信月度表bureau_balance.csv 记录的是“同一笔外部账户在不同月份的状态
变化”。因此，它不能直接和客户主表连接，而必须先回到账户这一层。当前代
码的处理顺序正是如此：先以账户编号为连接主键，把同一账户在不同月份的表
现压缩成一份账户摘要。这一层主要在回答三个问题：
（1）这笔账户一共留下了多少个月度记录；
（2）这些记录覆盖了多长的历史区间；
（3）各种账户状态在历史中分别出现得多不多。
为了回答这些问题，代码先把月度状态转成一组 0/1 指示，再按账户分组求
平均值。这样得到的结果，本质上就是“某种状态在这笔账户历史中出现的比例”。

用一个例子来理解：如果某笔账户有 10 个月记录，其中 8 个月处于正常

就是把过程性记录改写成稳定的统计画像。
（1）负债占总授信的比例高不高；
（2）逾期金额占负债或授信的比例大不大；
（3）账户是否真实存在负债，是否出现过逾期；
（4）账户开启、结束、更新这些时间点之间是否透露出异常或不稳定。

（1）数量类问题：这个客户历史上有多少笔外部账户；
（2）规模类问题：这些账户对应的授信、负债和逾期总量有多大；
（3）水平类问题：平均来看，这个客户的账户规模和风险水平如何；
（4）极端类问题：最严重的一笔账户、最大的逾期、最大的负债分别是什
么；
（5）时间类问题：这些历史账户离当前申请是更近还是更远，结束时间分
布集中还是分散。

1 模型优化
1.1 模型选择与参数设置
本项目采用 XGBoost 和 LightGBM 两种梯度提升树模型，对用户违约风
险进行二分类预测。二者都属于 Boosting 集成学习方法，适合处理结构化表格
数据，能够较好地学习特征之间的非线性关系与交互关系。
在代码实现中，使用的是xgboost.XGBClassifier 和lightgbm.LGBMClassifier
接口，即 Python 环境下常用的原生 GBDT 模型封装形式。这种方式便于参数
管理、训练控制和结果输出。
对于要使用的模型，可以通过参数的调节来使得模型达到近优。对于树模型
而言， 参数优化主要围绕以下几个方面展开：
（1）learning_rate：控制每一轮迭代的步长，值越小，模型学习越平稳，但
通常需要更多迭代轮数。
（2）n_estimators：表示迭代次数或树的数量，通常与学习率配合调整。
（3）max_depth 或 num_leaves：用于控制单棵树的复杂度，复杂度过高容
易过拟合。
（4）subsample 与 colsample_bytree：分别表示样本采样比例和特征采样比
例，可用于增强模型泛化能力。
（5）min_child_weight、min_child_samples、reg_alpha、reg_lambda：用于约
束树的分裂和控制模型复杂度，进一步抑制过拟合。
在实际调参过程中，上述参数并不是彼此独立的，而是相互配合、共同影响
模型效果。其中，learning_rate 与n_estimators 往往需要联合考虑：当学习率较
小时，通常需要更多迭代轮数来弥补单轮更新幅度较小的问题；而当学习率较大
时，虽然训练速度更快，但更容易出现震荡或过拟合。类似地，max_depth、
num_leaves、min_child_weight、min_child_samples 等参数决定了模型对训练数据
细节的拟合能力，需要在“模型表达能力”和“泛化能力”之间取得平衡。
一般来说，树模型调优可以按照“先粗调、后细调”的思路进行。首先确定较
合适的学习率和迭代轮数范围，保证模型具备基本的学习能力；然后再调节树的

1.2 利用交叉验证/验证集进行优化
由于结果的线上提交次数是有限的，这个时候，我们就需要构建稳定同步的
线下验证，来优化模型。通常对于线下验证，我们会使用两种方法，第一种就是
对训练集进行交叉验证，选择出最优模型；第二种就是把数据单独划分出验证集，
利用验证集来优化。具体来说，就是我们往模型上加减特征或者改变模型参数，
如果模型在验证集上表现的特别好，那么我们就认为模型在测试集上也会有相应
的表现（当然，要保持这种同步的话，对于验证集选取就显得非常重要）。
具体来说，代码使用 train_test_split 将训练数据按 8:2 划分为训练集和验
证集，并通过 stratify=y 保证两个数据集中正负样本比例基本一致。由于违约预
测任务通常存在类别不平衡问题，因此分层抽样有助于提高验证结果的可靠性。
在模型训练过程中，引入了 EarlyStopping（早停）机制：XGBoost 设置
early_stopping_rounds=50，LightGBM 使用 lgb.early_stopping(50)。
即当验证集 AUC 在连续 50 轮内没有明显提升时，训练自动停止。这样可
以在避免过拟合的同时，自动找到较合适的迭代轮数。
本次实验运行得到的验证集结果如下：
（1）XGBoostvalidationROC-AUC：0.780426
（2） LightGBMvalidationROC-AUC：0.779443
在验证集上完成参数优化与轮数选择后，代码进一步根据模型的最佳迭代轮
数，重新使用全部训练数据进行最终训练。先利用训练集和验证集训练模型；通
过 earlystopping 得到最佳迭代轮数；固定该轮数后，用完整训练集重新训练最
终模型；再对测试集进行预测。
这样做的原因在于：验证阶段的主要目的是选择合理的模型复杂度，而最终
预测阶段则希望尽可能利用全部训练样本信息，以提升泛化效果。

的统计学习方法为后续机器学习奠定了基础，树模型在结构化数据任务中长期表
现优异，而近年来深度学习与大语言模型的发展，又进一步拓展了数据智能的应
用边界。技术形式在不断变化，但其中相对稳定的核心能力并没有改变，即对问
题的理解、对数据的分析、对方法的验证，以及对结果的理性判断。
所以需要同学们辩证地来学习。
